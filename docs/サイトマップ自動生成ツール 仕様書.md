### 1. 目的

既存ウェブサイトの全ページ構造を再帰的に巡回（クローリング）し、リプレイス計画の基礎資料となるページリスト（URL、タイトル、ステータス）を抽出する。

### 2. 主要機能

- **再帰的クローリング:** 指定された親ドメインからリンクを辿り、全ページを抽出。
    
- **ホワイトリスト方式のドメイン判定:**
    
    - 親ドメインは自動的に対象。
        
    - 実行時に指定したサブドメインのみをクロール対象に加える。
        
    - それ以外の外部リンク（SNS、外部サービス等）は除外。
        
- **データ抽出:** `URL` / `Page Title (<title>タグ)` / `HTTP Status Code` を取得。
    
- **レポート出力:** CSVまたはExcel形式での書き出し。
    

### 3. 非機能要件（負荷対策・マナー）

サーバーへの負荷を最小限に抑えるため、以下の制御機能を実装します。

- **リクエスト間隔の設定 (Delay):** 1リクエストごとに 1.0〜3.0秒（可変）の待機時間を設ける。
    
- **同時接続数の制限:** 並列処理は行わず、シングルスレッドで1ページずつ取得する。
    
- **User-Agentの設定:** クローラーであることを明示する独自のUser-Agentを設定。
    
- **重複クロールの防止:** 一度訪問したURLはハッシュリストで管理し、二度アクセスしない。
    

---

### 4. 推奨する追加要件（実務的な視点）

効率的なリプレイスのために、以下の項目も検討に含めることをお勧めします。

|**項目**|**内容**|**理由**|
|---|---|---|
|**階層深度の制限**|最大○階層まで、という制限設定|無限ループや不要な動的パラメータページの巡回防止。|
|**特定ディレクトリの除外**|`/wp-includes/` や `/temp/` などを除外|不要なシステムファイルの混入を防ぐ。|
|**Basic認証対応**|ID/Passの入力機能|テスト環境や非公開環境の調査に必須。|
|**Content-Type判定**|HTMLのみを対象にする|PDFや画像ファイルへのリクエストをスキップし、負荷を下げる。|
|**最終更新日(Last-Modified)**|HTTPヘッダーから取得|移行の優先順位付けに役立つ。|

### 6. 技術スタック候補（例）

制作のしやすさとライブラリの豊富さから、以下の構成が一般的です。

- **言語:** Python
    
- **ライブラリ:**
    
    - `requests` (HTTP通信用)
        
    - `BeautifulSoup4` (HTML解析・リンク抽出用)
        
    - `pandas` (CSV出力・データ整理用)
        
- **実行環境:** ローカルPC（CLIツール）または Docker
